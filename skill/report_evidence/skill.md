# Report evidence workflow

先确定当前位流、器件、工具版本和报告范围。将基线、当前实现、实板与用户反馈分开列出，保留原始文件不改写。

为每个关键数字指明原始文件和条件。不要把显示配置当实测速率、正时序余量当全接口签核、文件校验当现场动作证明。

编辑manifest列出需验证的路径、SHA256和可选contains字段；用check_manifest.py核对。清单不通过时先检查版本与数据源，不自动重写期望值。

解释输出覆盖范围，明确未记录、未验证和用户反馈；只有成功文件校验时不宣称板卡或模型全部通过。报告更新后渲染逐页检查，再把图像占位清单单独交付。
