# 智察考场完整演示流程与演讲词

版本日期：2026年10月30日。依据AMD自主选题初级组指南第3.3节安排，建议准备8至10分钟展示素材，再按赛事正式视频时长要求剪辑；指南本节没有规定固定视频时长。先展示FPGA实物、状态机、视频、存储与接口，再展示智能体复核和可复现材料。

## 1 准备与启动

准备手机、指定紫色封面书、不透光遮挡物和演示名册。两路相机共同覆盖头部、双手和桌面；语音SCL为C14、SDA为C15。正常试卷、答题纸不作为资料目标，衣服、裤子、笔袋不作为目标。没有试卷实物时不把该项说成已经实测。

本次两板已固化并确认断电自启，日常只接通电源，无需重新下载或按RESET。双击启动脚本，或在PowerShell粘贴下一行：

```powershell
& 'D:\fpga_real\start_examguard.cmd'
```

上位机保持运行，核对串口COM5/COM12及网络接收状态，使用演示名册。Agent页点“当前会话”，图像回放目录选D:\fpga_real\src\pc\host\evidence_out。JoyCode页点“刷新联动”，确认两边是同一会话、同一目录。模型配置已保存时直接选择“大模型API”，不反复清空密钥。

演讲词：这是智察考场双芯协同监考系统。K230负责视觉识别，AMD Artix-7 FPGA负责考试流程、显示和历史图像，电脑负责管理与复核。今天会先展示板上完整流程，再展示老师如何通过对话找到事件及原始图像。

## 2 身份核验和正式开考

镜头先拍系统全景和两块板上电画面，再切HDMI与上位机。考生正对K230完成核验，电脑匹配名册，HDMI显示姓名考号，按语音核对。信息正确后由监考员按S3授权，再按屏幕与语音完成准备确认。看到“考试中”和倒计时后进行后面的异常展示。不要只在候考或交卷阶段测试遮挡。

演讲词：识别到人脸后，系统先显示姓名与考号，确认无误后才允许开考。准备阶段不扣考试时间，正式开考后FPGA独立维护状态与倒计时，考中求助也不会暂停计时。

## 3 板上识别与事件取证

先正常摆手几秒，说明大动作不应触发遮挡。再把真手机放入共同视野，停稳至系统出现疑似手机提示后移开。把紫书封面完整朝向镜头、停稳至资料提示后移开；不要只展示书脊。左右转头按当前识别提示展示，未产生事件时如实说明本次未识别，不伪造事件。最后完全遮住OV5640约5秒并移开，拍到HDMI提示与语音。

一次动作只展示一个目标，两次事件之间留几秒。每次事件后至少等待后2秒采集完成，再等待图像上传与状态更新；不要把暂未到齐的图像说成丢包。选中事件看完整event_ref和证据帧数。需要快速展示时用下方已验证存档路线，不必重复做动作。

演讲词：系统把这些结果作为疑似线索。FPGA持续保存过程画面，事件发生后按原时间保留前后各2秒。电脑同时检查图像分片和采集结果，老师可回看事件前后，而不只看到一个报警标签。

## 4 日常Agent的完整演示语句

打开“Agent 复核助手（日常查询）”，选择“大模型API”。每条等返回后再发下一条，保留问题下方的工具核验记录和实际响应模型。没有某类事件时应显示无匹配记录。

### A1 先确认数据源与状态

```text
请调用 get_system_health，说明当前选定会话、最后状态时间和考试阶段。区分最后上报健康、数据是否停更，以及能否证明设备现在在线。未知温度如实说未知。
```

### A2 查询手机并核对一条证据

```text
请调用 get_recent_events(time_range=1440, event_code=80, limit=3)，只选择返回的最新一条疑似手机事件，再调用 check_evidence_status 和 get_image_path。用简洁中文说明事件类型、时间、完整event_ref、收到与预期帧数及可查看图像。没有匹配事件就说明没有，不编造记录。
```

### A3 查询紫书资料线索

```text
请调用 get_recent_events(time_range=1440, event_code=81, limit=3)，只复核最新一条事件的证据状态和图像。说明这是疑似资料线索，类型以event_code为准；仅凭报警不能确认画面中一定是指定紫色封面书。
```

### A4 查询扭头线索

```text
请调用 get_recent_events(time_range=1440, event_code=96, limit=3)，只核对最新一条疑似扭头事件的证据状态。说明可复核范围，不根据少量帧推断持续时长或作弊意图；没有事件时如实说明。
```

### A5 实际看图

先选中A2或A3查询返回的真实事件，点“打开该事件的图像回放”，拍到原图，再返回点“AI 看图复核（最多发送3帧）”。这是按钮操作，不是只发一句“看图”。拍到实际发送帧数、模型名和辅助观察。没有图像时换一条确有图的事件；不要伪造图片。

演讲词：普通提问让文本模型调用只读工具，只有我主动点击看图才发送最多3帧给视觉模型。这里能核对模型实际看过哪些帧。抽样观察帮助老师定位线索，不能替代整段回放，更不能直接裁定作弊。

每完成一次查询或看图，及时点“导出本次复核记录”并用不同文件名保存；下一次查询会替换本次待导出的记录。不要一次让模型复核20条事件，最多6次工具调用会触发保护。遇到此提示时改用上面单条语句；已有工具结果仍可查看，不能称整个查询已完成。

## 5 JoyCode专业智能体演示

在日常Agent输入框写“请专业复核这条事件的证据完整性”，选中同一事件，点“（转到 JoyCode 专业复核）”。专业页点“（复制专业复核问题）”，打开JoyCode的“智察考场·证据复核助手”粘贴发送。这个自动生成的问题已经包含完整引用，不需要每场手改编号。

第一次或迁移电脑时，在专业页点“复制 MCP 配置”，到JoyCode中替换examguard配置并启用、重连；同一配置跟随上位机选择，不必每次改JSON。后续只需保持监考台打开、MCP启用，切场次后先重新查询状态或事件。JoyCode聊天在JoyCode内部，本页提供数据联动和原图回放。

### J1 查询系统来源

```text
请实际调用 examguard 的 get_system_health，报告当前选定会话、数据来源、最后状态时间和阶段。MCP本次调用成功不等于设备实时在线，live_session=false或stale请按原值说明。
```

### J2 列出最近少量事件

```text
请调用 get_recent_events(time_range=1440, limit=5)，列出事件UID、event_code_hex、事件名称和完整event_ref。不要把UID转成事件类型，不需要在本条问题中继续逐个查图。
```

### J3 核对刚才的一条事件

```text
请只对上一条工具结果中的最新一条事件，使用它的完整event_ref调用 check_evidence_status 和 get_image_path。说明真实事件类型、证据状态、收到和预期帧数、可查看图像数量及是否展示截断；本次只有路径元数据时，明确尚未目视复核。
```

### J4 展示规则约束

```text
结合刚才的真实工具回执回答：缺图能否确定是UDP丢包？历史记录显示正常能否证明设备现在在线？证据完整能否直接判作弊？请说明依据，不补造图片、网络原因或违规结论。
```

点击“（Skills / Rule / Prompt）”展示自己的配置参考，说明Rule匹配规则为*且只适用于本助手；内置工具仅选阅读，监考事实通过MCP查询。可自定义工作流不等于已训练模型权重。

把JoyCode返回的同一完整event_ref粘贴到专业页，点“打开事件图像回放”，再点“（转到 Agent 日常复核）”。确认回到同一场、同一事件。若切换数据源导致旧交接失效，先重新查询再转交，不能用同UID代替完整引用。

演讲词：日常Agent方便老师快速询问；专业JoyCode允许自己配置Skills、Rule、Prompt和MCP流程。两者共用同一份已选数据，通过完整事件引用交接。专业智能体负责组织复核，底层硬件继续负责实时采集和证据固化。

## 6 本机网页访问完整流程

放在最后展示。网页启动时固定所选会话、目录和模型模式；需要切换时先停止网页，再修改，再启动。

在Agent页找到“网页访问密码”，点“（生成密码）”和“（保存并应用密码）”；若已有保存密码可直接用。点“启动本机评审网页”，再点“（复制地址）”或“（打开网页）”。在同一电脑浏览器访问界面显示的真实地址，账号judge，密码使用刚保存的值。端口可能变化，不使用写死的地址；127.0.0.1仅本机可访问，不能发给外地评委当公网链接。

### W1 网页状态查询

```text
请调用 get_system_health，说明当前所选会话的阶段、最后状态时间和数据来源，未知字段如实说明。
```

### W2 网页事件与证据

```text
请查询最近1440分钟疑似手机事件，只选择最新一条，核对证据状态和现有图像。没有匹配事件时如实说明；不要直接判断作弊。
```

网页若以“本地工具演示”模式启动，改用这两句固定规则支持的问题：

```text
系统健康和温度怎么样？
```

```text
最近1440分钟有没有手机报警？
```

在网页选择工具返回的事件查看图像，点“下载本次复核记录”。网页提供文字和证据查询，AI看图仍在桌面按钮中操作。随后“退出登录”，演示返回登录页。

可选密码安全镜头：网页登录后，在桌面生成并应用新密码，使用桌面显示的新地址访问，旧登录和旧密码应失效，新密码可登录。旧地址失去连接可能是服务重建；不反复刷新旧页。录屏时遮住密码与密钥。最后点“停止评审网页”，网页应停止服务。

演讲词：本机评审网页让同一电脑浏览器也能访问已选数据。它有独立登录、查询和导出，修改密码后旧登录失效。目前展示的是本机入口，远程公网评审需要另行部署。

只在实时动作不便或需稳定展示时使用，并明确说“下面展示已保存的真实场次”。选择capture_20261030T092232_ad8a267501f54cbfbb78428fc697180b.sqlite3及对应证据目录，JoyCode刷新数据源。该场记录的UID10为0x64遮挡，用户此前核对为41/41联合完整；新查询结果始终以当前工具回执为准。

下面语句可原样粘贴到大模型Agent或JoyCode，不受旧事件超出24小时列表范围影响：

```text
请对当前选定会话中event_ref为000000010000005E00000001000000000000000A000000000000F2F803003564的事件调用check_evidence_status和get_image_path。分别报告UID、事件类型、收到和预期帧数、证据状态及图像展示是否截断；只依据本次回执，不直接判断作弊。
```

## 8 展示资源报告和技能包

打开原始资源报告，对比基线41773与当前41811个LUT，寄存器46296变46268，BRAM70.5与DSP3不增加。当前建立余量+0.217ns、保持余量+0.026ns，说明是已有约束下结果；跨时钟告警和外部接口预算仍按原报告保留。不要说零延迟、零遗漏、100%准确或所有时序完全签核。

打开skill目录的README与collaboration_record.md，展示一次UID与类型混淆、如何补工具字段和回归、用户复测如何纠正。展示report_evidence清单校验结果。通用报告核验技能可换到其他FPGA项目；它不是PYNQ技能，不把此项当成PYNQ额外加分。

结束演讲词：这个作品把FPGA实时流程、事件前后取证和自然语言复核连在一起。我们保留了原始报告、构建脚本、实测记录和协作纠错，既展示功能，也让结果能被核对和复现。最终是否违规仍由老师结合原始图像判断。

## 10 常见情况的处理

提示找不到examguard工具：到JoyCode启用MCP并重连，不重刷板卡。没有近24小时事件：确认是当前场次且已有动作；旧场次按完整引用查，不修改电脑时间。证据not_received：核对会话和目录，不直接说丢包。图像仅32张且display_truncated=true：是展示上限，不代表总帧数32。看图发送3帧：是抽样，不是全部录像。模型繁忙：等待程序按已保存配置切换，记录真实结果，失败则明确失败。网页失联：先核对桌面是否仍运行及最新地址。上述问题都不要求重新烧写已经通过的Flash。
