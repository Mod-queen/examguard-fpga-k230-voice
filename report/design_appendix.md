本文件保留优化、协作与复现的技术配套资料。简明内容已合入design_report.docx附录A—D，便于评委在一份总设计文档中阅读；原始报告和完整脚本仍由仓库提供。

## 优化依据与结果

旧版本容易把大动作当遮挡，身份信息黑底也占用过多画面。此次优化针对这两个具体问题，不是提升模型整体准确率。

| 指标 | VOICE3基线 | 当前rev03 |
| --- | --- | --- |
| LUT逻辑单元 | 41773 | 41811 |
| 寄存器 | 46296 | 46268 |
| BRAM片上存储 | 70.5 | 70.5 |
| DSP计算单元 | 3 | 3 |
| 建立时间余量 | +0.103ns | +0.217ns |
| 保持时间余量 | +0.020ns | +0.026ns |
| 身份背景面积 | 22528像素 | 7488像素 |
| 遮挡判断 | 旧画面变化策略 | 有效画面98%近黑，连续30帧确认、3帧释放 |

逻辑单元增加38，约0.091%；寄存器减少28；背景面积减少约66.8%。没有增加BRAM和DSP。原始同器件、同Vivado版本的报告在build/reports/baseline与current。正时序余量不等于极限频率提升。

系统控制50MHz、显示约74.25MHz，其他时钟见原始timing.rpt。当前报告内部无未约束时钟/端点，但仍有18项CDC Critical汇总及29个输入、48个输出未设置外部delay的预算说明，不将其隐去或称为全部接口签核。当前功能仿真和实板演示不能替代这部分边界的完整证明。

近黑定义为RGB三通道均不高于31。30帧在60Hz下名义约0.5秒，只是策略推导，不是端到端报警延迟实测。用户确认摆手不误报、全遮有提示与语音；没有独立整场误报率统计。1GiB DDR旧独立测试写约1.280GB/s、读约0.836GB/s，不是当前整机共享运行吞吐率。

## 大模型协作与工作流

可见提示词、答复节选及纠错见llm_visible_excerpts.md；完整整理脉络见collaboration_record.md。只提交可见内容，不补造内部推理或完整平台原始导出。

日常Agent流程：问题→选择只读工具→读取所选会话→解释真实返回→老师回放。视觉复核由用户主动触发，最多发送3张校验通过的帧。JoyCode通过MCP调用相同四工具，可配置Skills、Rule和Prompt；双方交接同一事件与数据源，仍由老师最终判断。

实际纠错包括UID误当类型、缺图直接归因丢包、历史状态误当当前在线。修正先补工具类型和范围字段，再调整提示、规则和回归。查不到图不能推断设备未采集，41帧完整、工具列32帧和模型看3帧是不同范围。

## 技能如何提炼

report_evidence从基线/当前混用及报告无来源等观察提炼为文件清单核查：先固定文件SHA256，再检查关键原文。用本包六项真实原始文件校验验证，边界是只证明所列文件一致，不能证明现场动作或准确率。

examguard_review从UID、来源、缺图和历史状态错误提炼为只读复核流程，迁移到工业告警等题目时须替换类型表与工具契约。对应单测和MCP子进程记录在sim/original_logs/agent，各目录readme.md列出使用和失效条件。两项都不是PYNQ专用技能，不以其申请PYNQ额外加分。

## 从零复现入口

按根目录readme.md顺序准备器件、Vivado2018.3、Python3.12与匹配CanMV固件，构建FPGA、准备SD和新用户身份，再启动PC，最后执行仿真与完整演示。当前板已固化，日常演示只需上电与启动PC。

本包不包含个人生物特征、私有密钥或固件镜像。新板必须取得匹配厂商固件并登记本人身份。包内验证与新路径全量重建结果各单独记录，不把本次新生成位流称为已上板验收。
